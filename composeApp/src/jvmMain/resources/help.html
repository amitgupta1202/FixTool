1. Getting Started

What is FixTool?

FixTool is a desktop application for working with the FIX (Financial Information eXchange) protocol. It allows you to:

  • Connect to FIX servers and receive messages
  • Send FIX messages with custom field values
  • View and analyze message history
  • Search and filter messages
  • Create reusable message templates

Quick Start

  1. Click the New Connection button in the toolbar
  2. Enter your connection details (host, port, SenderCompID, TargetCompID)
  3. Click Connect to establish a FIX session
  4. Messages will appear in the grid view as they are sent/received
Tip: For testing, use the Demo Server option which starts a local FIX server that echoes messages back.

2. Managing Connections

Creating a Connection Profile

Connection profiles store your FIX session configuration for reuse:

  1. Click New Connection in the toolbar
  2. Fill in the connection details:
    • Profile Name: A friendly name for this connection
    • Host: FIX server hostname or IP address
    • Port: FIX server port number
    • SenderCompID: Your FIX session identifier
    • TargetCompID: Server's FIX session identifier
    • BeginString: FIX protocol version (e.g., FIX.4.2, FIX.4.4)
  3. Click Save Profile to save for later use
  4. Click Connect to start the session

Demo Server

The demo server is perfect for testing:

  • Starts a local FIX server on port 9876
  • Automatically accepts all messages
  • Echoes messages back with a 1-second delay
  • No external dependencies required

3. Viewing Messages

View Modes

FixTool provides two view modes for messages:

Mode Description Best For
Grid View (Parsed) Shows messages in a structured grid with columns for common fields (Time, Direction, SeqNum, MsgType, Summary) Quickly scanning message flow, identifying patterns
Terminal View (Raw) Shows raw FIX messages as text with SOH (|) delimiters Debugging, seeing exact message format

Toggle between views using the view mode button in the toolbar (grid icon / terminal icon).

Message Details

Click any message in the grid to view detailed field information in the detail panel:

  • Shows all FIX fields with tag numbers and values
  • Displays field descriptions from the data dictionary
  • Shows repeating groups in a hierarchical view
  • Toggle protocol tags visibility (BeginString, BodyLength, CheckSum)

Expanding Messages

In grid view, you can expand messages to see all fields:

  • Click the arrow icon or double-click a message row
  • Fields are displayed with tag numbers and descriptions
  • Collapse by clicking the arrow icon again

4. Sending Messages

Opening the Message Editor

Click the Message Editor button in the toolbar to open the message editor panel.

Building a Message

  1. Click Add Field to add a new field row
  2. Enter the Tag number (e.g., 35 for MsgType)
  3. Enter the Value (e.g., D for NewOrderSingle)
  4. Repeat for all required fields
  5. Click Send to send the message

Example: New Order Single (35=D)

Tag 35: D          (MsgType = NewOrderSingle)
Tag 11: ORDER123   (ClOrdID = Order ID)
Tag 55: EUR/USD    (Symbol)
Tag 54: 1          (Side = Buy)
Tag 38: 1000000    (OrderQty)
Tag 40: 2          (OrdType = Limit)
Tag 44: 1.0850     (Price)

Saving Message Templates

Save frequently used messages for reuse:

  1. Build your message in the editor
  2. Click Save Message
  3. Enter a template name
  4. Load it later from the Saved Messages dropdown

5. Message Templates (Advanced)

What are Template Expressions?

Template expressions allow you to dynamically generate field values using Kotlin expressions. This is especially useful for:

  • Generating unique IDs automatically
  • Inserting current timestamps
  • Referencing values from previously received messages
  • Creating responsive message workflows

Template Syntax

Template expressions are enclosed in ${...} and evaluated when you send the message:

Basic Templates

Template Result Description
${UUID.randomUUID()} a1b2c3d4-e5f6-... Generate random UUID
${System.currentTimeMillis()} 1705419265123 Current Unix timestamp
ORDER-${UUID.randomUUID()} ORDER-a1b2c3d4-... Prefix with text

Timestamp Formatting

${LocalDateTime.now().format(DateTimeFormatter.ofPattern("yyyyMMdd-HH:mm:ss.SSS"))}

Result: 20250116-14:32:45.123

Common patterns:

  • "yyyyMMdd" → 20250116
  • "HHmmss" → 143245
  • "yyyyMMdd-HH:mm:ss" → 20250116-14:32:45

Message References (Advanced)

Reference field values from previously sent or received messages:

Syntax

${incoming["MsgType"].valueOfTag(TagNumber)}
${outgoing["MsgType"].valueOfTag(TagNumber)}
  • incoming - References latest received message of that type
  • outgoing - References latest sent message of that type
  • "MsgType" - FIX message type (e.g., "D", "R", "AJ")
  • TagNumber - FIX tag number to extract

Real-World Example: Quote Response

Scenario:

You receive a QuoteRequest (35=R) and want to send a QuoteResponse (35=AJ) that references the original request:

Incoming QuoteRequest:

35=R              (MsgType = QuoteRequest)
131=QUOTEREQ-001  (QuoteReqID)
55=EUR/USD        (Symbol)
38=1000000        (OrderQty)

Your QuoteResponse Template:

Tag 35:  AJ                                      (MsgType = QuoteResponse)
Tag 131: ${incoming["R"].valueOfTag(131)}       (Same QuoteReqID from request)
Tag 55:  ${incoming["R"].valueOfTag(55)}        (Same Symbol from request)
Tag 117: QUOTE-${UUID.randomUUID()}             (New unique QuoteID)
Tag 132: 1.0850                                  (BidPx)
Tag 133: 1.0852                                  (OfferPx)

Resolved Message (when sent):

35=AJ                                    (MsgType = QuoteResponse)
131=QUOTEREQ-001                         (Matched from incoming)
55=EUR/USD                               (Matched from incoming)
117=QUOTE-f7e8d9c6-1234-5678-...        (Generated UUID)
132=1.0850                               (BidPx)
133=1.0852                               (OfferPx)
Tip: Message references always use the latest message of each type. The application tracks incoming and outgoing messages separately across all sessions.

Common Message Types

Type Name Common Tags
D NewOrderSingle 11 (ClOrdID), 55 (Symbol), 54 (Side)
R QuoteRequest 131 (QuoteReqID), 55 (Symbol), 38 (OrderQty)
AJ QuoteResponse 131 (QuoteReqID), 117 (QuoteID), 132 (BidPx)
8 ExecutionReport 11 (ClOrdID), 37 (OrderID), 17 (ExecID)
Note: If a referenced message type doesn't exist (not received yet), the expression will evaluate to null. Make sure you've received the message before referencing it.

6. Searching Messages

Global Search

Search across all sessions for messages containing specific text:

  1. Click the Search button in the toolbar
  2. Enter your search query (searches in all fields and values)
  3. Press Enter or click Search
  4. Results show matching messages with context
  5. Click Open in Search Window to pin results

Search Results Pane

The search results pane shows all matches in a persistent grid:

  • Appears at the bottom of the window
  • Shows session name, time, direction, message type, and matched content
  • Click any result to navigate to that message in its session
  • Resizable and stays open while you work
  • Close with the X button when done

7. Filtering Messages

Global Filter

Filter messages across all sessions using the global filter controls:

  • Regex Pattern: Enter a regular expression to match messages
  • In/Out Checkboxes: Show/hide incoming or outgoing messages
  • Filters apply to all open sessions simultaneously
  • Clear filters by clearing the regex and checking both boxes

Example Filters:

  • 35=D - Show only NewOrderSingle messages
  • EUR/USD - Show only messages mentioning EUR/USD
  • ClOrdID=ORDER.* - Show orders with IDs starting with ORDER

8. Settings

Data Dictionary

Configure a FIX data dictionary for field descriptions:

  1. Click Settings in the toolbar
  2. Click Browse next to Data Dictionary Path
  3. Select your FIX XML data dictionary file
  4. Click Save

The dictionary provides human-readable names for tags and values.

Custom Grid Columns

Add custom columns to the grid view:

  • Enter tag numbers (comma-separated) in the Grid View Columns field
  • These tags will appear as additional columns in the grid
  • Useful for frequently referenced fields

Validation Settings

  • Validate Fields Out of Order: Warn if fields are not in tag order
  • Validate Fields Have Values: Warn if required fields are empty

Data Directories

Configure where FixTool stores profiles and templates:

  • Connection Profiles Path: Location for saved connection profiles
  • Saved Messages Path: Location for saved message templates

Useful for version control or sharing configurations across systems.

Rejection Rules

Configure which messages should be highlighted in red as rejections:

  • Add rules with message type and optional additional tag matching
  • Default rules: 35=3 (Reject), 35=j (Business Reject), 35=9 (Order Cancel Reject)
  • Add custom rules for your specific workflow
