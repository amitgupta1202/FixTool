The Load Run Dialog, in Sections

Four sections with a purpose each, the first two open, the last two folded with their state written on the fold, one plain sentence per row, and a window you can read. Plus the answer to "where do templates come from, and how does a set hold three messages".

The dialog has ten rows at one weight, an explainer in monospace grey under each, three section labels at nine points that read as more grey, a label column too narrow for the word "note", and a fixed window of 640 by 580. It is not that there is too much. It is that nothing says where to start. Sections with rank fix that, and folding the two sections a first run does not need makes the first view four rows.

Sections, without the overwhelm. A section is open when a first run needs it and folded when it does not. A folded section carries a one-line summary of what it holds, so nothing is hidden, and it opens itself when a refusal names something inside it. That is the run-configuration idiom: the configuration open, "Before launch" folded with its state on the fold.

Where templates come from, and how a set holds three messages

A template is a saved message. You build it in the message editor, press Save, and name it. It is stored in the workspace and tagged to the profile you were on. The Load run dialog's picker lists those messages, the issuing profile's first. The editor's Load button skips the picker and uses the message in the editor as it stands.

A set does not hold three messages in one template. It holds one phase per message the client sends, and each phase names its own saved message. The messages the venue sends back are not authored at all: they are what a phase matches and, when asked, captures values from. So the RFQ round trip is three saved messages and three phases, and the Quote in the middle belongs to the venue:

To build one from nothing: save the three messages in the editor, open Run ▾ → Load sets…, add a set, add a phase per message, tick the capture on phase 1, and Run set. The shipped RFQ example already has all three messages and the set, which is why it appears in Run ▾ as soon as the example is opened fresh.

Order of work

  1. The window and the words. 780 by 700, resizable, remembered in the view-state store. Every explainer replaced by the sentence in the table above, in the sans face. "Settle" becomes "Wait for replies" in the dialog only. The note marker becomes an icon. LoadRunDialog.kt:88, the Sub and GroupHead composables, Notice
  2. The sections and folds. Four sections with heading and purpose. The last two as folds with a summary line built from the plan (match, reply type, listen profiles, seed names and values, store). Advanced's existing auto-open on a refusal becomes the fold's. Compose tests: the summary text, a refusal opening its fold, the other fold staying closed. LoadRunDialog.kt, Where.ADVANCED and placeOf
  3. The five behaviours. A self-referencing or generator seed value rendered once or refused. The acceptor excluded from Also listen on. The Store row collapsing to a sentence when the profile agrees. "view in editor" opening the editor panel and bringing the window forward. Each with a test. Decisions

decidedFold, or show everything?
Fold the two sections a first run does not need, with their state on the fold. Everything visible at one weight is what made ten rows feel like thirty.
decidedRename Settle?
In the dialog, yes: "Wait for replies". The report and the CLI keep "settle", because they are read by people who know the engine and by scripts.
assumedThe same sections in the phase editor.
The phase editor is this dialog's body in phase mode, so it gets the sections for free, minus the Identity fold, which is the set's.
