One Grammar for Every Pane

The toolbar note gave each control a kind and a place. This one gives every pane, dock and dialog the same five things: one header, one name, one way to show a state, one word per action, and one way to lose something.

The panes grew the way the toolbar grew, one feature at a time, and each of them got the header that made sense the week it was written. The audit found ten distinct header patterns across the panes, twelve phrasings for closing something, seven for clearing something, four words for a blank line, four vocabularies for connecting, and toggles that show their state by tint, by icon swap, by text, by background fill or not at all. None of it is wrong on its own. Each component was designed well against itself: the trace header is a good trace header, the load documents lead with a verdict badge because a run has a verdict, the editor folds its buttons because eleven of them were never going to fit. They were never designed against each other.

The grammar. One, a dock has one header: the noun from its stripe tab, an optional status in smaller type, the actions, a Hide. Two, a name is one noun, and it is the same word on the stripe, the header, the tooltip and the help. Three, a toggle looks pressed when it is on, never tint alone and never an icon swap alone. Four, one verb per action, sentence case, and a pane action and its all-panes twin share the verb and differ only in the object. Five, losing something either arms (click again) or confirms inline, never in a dialog and never silently.

The one line in that table that changes a shortcut rather than a string is Search. Today ⌘F opens Search all sessions from the app root, while the pane's own search button advertises "Show Search (Ctrl+F)" and opens something else, so the only shortcut printed in a pane tooltip is the one shortcut that does not belong to that button. After: ⌘F searches the focused pane and falls back to Search all sessions when no pane has focus, and ⌘⇧F is always Search all sessions. That is IntelliJ's find in file and find in path, in the same order. It amends the toolbar note, whose filter row moves from ⌘⇧F to ⌥⌘F.

Losing something

Dialogs and the odd ones

  • The compose dialogs all take this header: Settings, Search all sessions, New workspace, Venue tag roles, Remap scenario and the template browser popup. The three 13px dialogs that have no close icon get one, so Esc stops being the only way out of a window that never told you Esc was the way out.
  • The native windows keep the OS title bar and carry no in-window title: Load run, Load sets, Help and the two diff windows. Help also moves from Material 2 widgets to Material 3 like the rest of the app, and its three names become one, "Help".
  • Settings' "Restore defaults" moves out of the header, where it sits one gap from the close button, into the footer's left side as a text action, and it confirms inline.
  • "Open in Search Window" becomes "Pin results", because what it opens is a pane in this window and the word Window in a button next to a dialog's Close means something else entirely.
  • The paged Workspace menu stays exactly as it is. It is the only multi-page menu in the app and this note has nothing against it.
  • Every icon button without a tooltip gets one: the editor's Hide, the terminal's chevron and close, the scenario dock's chevron, the raw search bar's three, step Up and Down in the scenario editor, Diff selected in the grid, the minimized strip's restore all, the rail's expand and collapse, and the notification toast's close.
  • The three grid header implementations, the message grid, the search results and the trace, share one GridHeader between them.
  • The Connection panel's local copies of SlimTextField, SlimCheckbox and SlimButton are deleted in favour of SlimComponents, which is where the other twenty components get theirs.

Order of work

Eight commits on main, each one whole. They run after toolbar steps 1 to 3, the stripes, the view controls and the filter row, because the dock headers take their titles from the stripe nouns and the pane header hands its filter controls to the filter row. They run before toolbar steps 4 and 5, the toolbar regroup and the menu bar, because those two need the names and the catalogue this note settles.

  1. DockHeader. One composable, adopted by the nine docks, with the stripe nouns as titles and a Hide tooltip on every one. The help text is updated wherever it names a panel. a new DockHeader.kt · the nine panels · the help content
  2. ToggleIconButton. The pressed look, replacing every tint-only and icon-swap toggle, and the Validate badge beside Send. TooltipButton.kt · TabBar.kt · SplitView.kt · MessageEditorPanel
  3. PaneHeader. One header for TabBar and SplitView with the fold rule, the pane vocabulary, ⌘F in the pane, and Close arming. TabBar.kt:324 · SplitView.kt SessionPanelHeader:572 · App.kt:265
  4. Vocabulary sweep. The table in section 6 applied to every string, sentence case throughout, one overflow glyph, a tooltip on every icon button. Mechanical, large, one commit, with a test that greps the UI sources for the retired phrasings ("Add Separator", "click to hide", "More Options", "Close Detail Panel" and the rest) so they cannot come back. every file in ui/ · a new UiStringsTest
  5. Editor header. Labelled chips, View ▾, overflow. MessageEditorPanel.kt, the BoxWithConstraints toolbar row
  6. Dialog chrome. DialogHeader, SlimSearchBar everywhere, Help to Material 3, the Settings footer, "Pin results". SettingsDialog.kt · HelpDialog.kt · SearchAllSessionsDialog.kt · the three 13px dialogs
  7. Losing something. Arm and inline confirm applied per section 7's three lists. ConnectionPanel · AcceptorRulesEditor · ScenarioEditor · LoadSetsDialog · SettingsDialog
  8. Shared grid header, and the Connection panel's local widgets deleted. HierarchicalGridView · SearchResultsGridHeader · TracePanel.kt:443 · ConnectionPanel

Then toolbar steps 4 and 5, the toolbar regroup and the menu bar, with the names and the catalogue this note fixed.

Decisions

decidedHide for tool windows, Close for content.
Hide. Nothing is lost when a dock hides, and the stripe tab brings it back with one click or one shortcut. A tab, a session or a document holds something, so it closes, and the two words stop being interchangeable in the twelve phrasings the audit found.
decidedThe pressed look is the only state language for toggles.
Pressed. Tint, icon swap and a changing label each failed somewhere in the audit: two toggles change only their icon, four change only their tint, and one changes its own label. Follow already uses a fill and reads well, and it adopts the shared look for consistency rather than because it was broken.
decided⌘F searches the pane, ⌘⇧F searches all sessions.
IntelliJ's pair. Find in file and find in path, in that order. The filter row moves to ⌥⌘F, which amends the toolbar note.
decidedNo confirmation dialogs anywhere.
Arm or confirm inline. The app already does each of them in exactly one place, so neither is a new idiom. A modal over the window is the one pattern this app has never needed, and it is the one that trains people to click through without reading.
decidedClear stays one click everywhere.
One click. Consistent with the toolbar note. A cleared pane refills the moment the next message arrives, so the cost of a mistake is a few seconds of scrollback rather than anything a person cannot get back.
decidedThe venue pane keeps Start and Stop.
Keeps them. Its own comment explains why a named verb beats a power icon for a listener, and the vocabulary allows the short form wherever the noun is already on screen, which it is: the venue's SenderCompID and port are the line above the buttons.
decidedThe Scenarios rail keeps its second row.
Keeps it. That row is the rail's content toolbar, the way the editor's button row is the editor's, and neither belongs in a header. Only the title bar above it changes.
assumedA retired-phrasings test.
A unit test that fails when a UI source contains one of the old strings. Cheap to write, and it is what makes a sweep of this size stick past the week it lands.
assumedSentence case is the house case.
The newer components already use it, the help already uses it, and the Title Case tooltips are the older half of the app rather than a decision anyone made twice.
openShould Close session arm, or should it not confirm at all like Disconnect?
Default in this note: it arms, because the log goes with it and there is no Recent for a closed session. The alternative is no confirmation and a Reopen in the tab strip for a minute, which is more to build and better for the person who closed the wrong pane.
openDoes the editor keep its own profile picker, or take the focused session from the pane area?
Default: it keeps it. Out of scope for a grammar, noted here so the editor step does not quietly decide it.
