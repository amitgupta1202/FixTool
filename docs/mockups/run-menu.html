One Run Menu

Where a saved run set, a load set and a load run are started from, why the Scenarios rail is the wrong place for two of them, and a Disconnect all button beside Quick Connect.

Today the only Run menu in the app is inside the Scenarios tool window's header. It grew there because scenarios were the first thing that could be run, and every runnable thing since was added to the same menu: run sets, fan-out, the load run, and now load sets. So somebody who wants to run RFQ round trip opens the message editor, finds a Load button, and gets a form for one message. A load set is not a scenario. It has no steps, no expectations and no bindings. Its only connection to the rail is that the menu was already there.

The door rule. A contextual door runs the thing in front of you and stays with it: the editor's Load button runs the message being edited, the rail's items run what the scenario list is showing. A named door runs a saved configuration by name, or opens the chooser, and belongs in one app-level Run menu. Every door opens the same dialog, prefilled, and the dialog says where the message came from.

Decisions

decidedToolbar, not a macOS menu bar menu.
Toolbar. Every app-level action FixTool has lives in the toolbar today, Quick Connect included, and the control surface has no menu bar to mirror. A menu bar Run could come later as a second door to the same menu.
decidedDoes the editor's Load button move?
No. It runs the message in front of you, which is the definition of a contextual door. Run ▾ → Load run… runs a saved message you pick. Both open the one dialog.
decidedWhere does Recent go?
Run ▾, as its own group. Recent is about records, not about the scenario list, and it already merges load and scenario runs. A menu about saved things should also be where you find what they produced.
decidedDoes Disconnect all ask first?
No. Reconnecting is one click and nothing is lost: books, records and panes survive a disconnect. The one case that would lose something is a live load run, and there the button is disabled and says why.
assumedNo keyboard shortcut yet.
The dialogs already take ⌘↵ to run. A shortcut for the menu itself can follow once the menu has settled where it is.
