FixTool · design note · 2026-09-09

Setup, Flow, Teardown

Setup and teardown steps became rows in the scenario editor today. One edit is still impossible: a step cannot change which of the three lists it runs in, so a scenario written without a setup cannot gain one. This note adds that control and closes the two smaller gaps beside it.

A captured scenario arrives with a Clear messages step in its setup, and that step is what erases the session log on every run. Until today the editor showed setup as one read-only sentence in its header, so the only way to keep the log was to open the JSON and delete the step by hand. Now setup and teardown steps are rows in the step list, badged SETUP and TEARDOWN, and they take the controls the list already had: mute, remove, re-order and the session picker.

What they do not take is a way in. Insert puts a new step into the phase of the selected row, which is right when a setup row exists and useless when none does. A hand-written scenario, or a captured one whose author removed the Clear step and wants it back, has nowhere to put a setup step.

What shipped

The gap

Why not let ↑ cross the line? Pressing ↑ on the first flow row could turn it into the last setup row: the row would not move, it would gain a badge. Ten lines of code, and a press of ↑ that visibly does nothing reads as broken. The boundary is the one place where "earlier" means "a different list", and that edit deserves a control that says so.

Runs in, in the detail pane

A step's phase is a property of the step, like its session, so it is edited where the step's other properties are: a runs in dropdown beside Session in the detail pane, in the same quiet-word register as on and waits up to. Choosing a different phase re-files the row to the end of that phase's segment, the selection follows it, and the header summary appears or retires in the same frame.

The rules of a re-file

QuestionAnswer
Where does the row land?At the end of the target phase's segment. Its place inside the phase is a second decision, and the arrows already make that one.
What travels with it?The row, its stable editor id, its mute state and its session. The detail pane is keyed on the id, so its drafts survive the move.
Where does the cursor go?With the row. A re-file that left the selection on whatever slid into the old position would open the wrong step's detail.
Which kinds get the control?Every kind. The runner has no per-phase restriction: a setup Send that logs in to a venue is legal today, and capture itself writes a Clear order book into setup.
What about numbering?Re-counted from the rows. The flow is numbered 1..n, setup and teardown rows carry no number in the list and are "Setup 1", "Teardown 1" in the detail title.
Is it undoable?By setting it back. The dropdown is its own undo, and the scenario is not saved until Save.

Two smaller gaps, closed in passing

Teardown has no test

Every test fixture in the repo has a setup step and none has a teardown step, so the teardown path is symmetric with setup and only compile-checked. Three tests on a fixture with a teardown Clear close it:

  • It lists last, below the flow, with the TEARDOWN badge.
  • Its ↑ is disabled at the flow boundary, and the flow re-orders above it without disturbing it.
  • Muting it and saving writes teardown[0].muted = true and leaves the flow untouched.

The step identity test gains one three-phase save, so a teardown step's id survives the partition with nothing left for withIds() to mint.

The hoisted selection can be negative

The editor reports its cursor as a flow index so a tab switch lands back on the same row, which makes a selected setup row a negative number. Nothing indexes with it today. One KDoc line on ScenarioDoc.Editor.selectedStep, saying it is a flow index and negative for a setup row, stops a future reader treating it as a list position.

Order of work

  1. The runs in dropdown and the re-file. A phase field is already on the row; this adds the control to the detail pane and one editor function that moves a row and its id to the end of a segment and re-selects. ScenarioEditor.kt · StepDetail, and the editor's step list state
  2. Its tests. A clear inserted into the flow and re-filed to setup saves into setup, the selection follows, the summary appears. The same row set back to flow saves as it started. ScenarioEditorTest.kt
  3. The teardown fixture and its three tests, plus the three-phase identity save. ScenarioEditorTest.kt · ScenarioEditorStepIdentityTest.kt
  4. The detail title's separator becomes a middle dot, matching the row label's Expect 8 · 2 tags. One line, every step's title. ScenarioEditor.kt · StepDetail
  5. Words. The KDoc line on the hoisted selection, one sentence in the setup ⓘ ("or insert a clear and set runs in to setup"), one sentence in the help page. ScenarioDocuments.kt · ScenarioEditor.kt · help.html

Decisions

decidedIn the detail pane, not on the row.
Detail pane. The row already carries a session, a glyph, a label, a badge, the variable chips and four tools. Phase is a property of the step and is edited beside its other property, the session, in the same register.
decidedThe re-file lands at the end of the target phase.
End of segment. A step moved into setup most often wants to be its last step anyway, and the arrows are there for the rest. Landing it at the start would put a new Clear before a captured Clear order book, which is the wrong order for a venue.
decidedEvery step kind may change phase.
Every kind. Restricting the control to clears and resets would encode a rule the runner does not have, and a scenario that logs in to a venue in setup with a Send is a real one.
decidedThe detail title separator is a middle dot.
Middle dot. Today it is an em dash, which the rest of the editor's labels do not use. "Setup 1 · clear" reads with "Expect 8 · 2 tags". It changes every step's title, and it is one line.
rejected↑ crosses the phase boundary.
Cheapest by far, and it would make the row's most-used control do two different things depending on where the row sits. The callout above has the rest.
rejectedA phase-aware Insert bar.
An "into: setup / flow / teardown" choice beside the six insert buttons is chrome for an action that happens once per scenario, and it still leaves an existing step unable to move.
decidedA menu item is one line, word and sentence together.
One line. The app's dropdown draws one text per item, and the matcher-type picker already writes its items as "word · what it does". A two-line item would need a new dropdown for one menu. Built this way on 2026-09-09.
decidedThe hoisted cursor is counted at the moment it is reported.
Counted live. Building this showed the editor reporting the cursor against a setup count one frame old, so a row that had just become setup came back from a tab switch on somebody else's row. The count is taken when the selection is reported, not from the composition.
assumedNo keyboard shortcut.
The dropdown takes focus and arrows like any other. A shortcut for the phase itself can follow if the edit turns out to be frequent, which nothing suggests.
assumedThe rail keeps listing the flow only.
The Scenarios rail shows a run's verdict per flow step, and the run report numbers the flow. Setup rows in the rail would need a verdict column of their own, which is a different note.
